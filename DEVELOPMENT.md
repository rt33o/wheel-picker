# Разработка WheelPicker

Этот файл позволяет начать новую задачу без истории первоначального чата. Правила работы агента находятся в `AGENTS.md`, пользовательская документация — в `README.md` и `README.en.md`, изменения версий — в `CHANGELOG.md`.

## Отправная точка

На момент подготовки этого руководства версия **1.5.2** слита в `main` через [PR #5](https://github.com/rt33o/wheel-picker/pull/5). Это состояние исходников; публикация GitHub Release и загрузка Setup выполняются отдельно. В дальнейшем сверяйте версию с файлами репозитория и GitHub.

Приложение работает самостоятельно и, по желанию, через PowerToys Run. Исходники, ассеты, адаптер, тесты и сценарий установщика находятся в одном Git-репозитории. Личные настройки и установленная копия находятся отдельно от исходников.

## Проект и отдельные чаты в Codex

1. Добавьте локальный проект **WheelPicker**, выбрав корень этого репозитория — папку с `.git`, `AGENTS.md`, `src` и `Build.ps1`. Не выбирайте одну папку `src` или родительскую папку с временными материалами.
2. Общие инструкции храните в `AGENTS.md`, устройство проекта и команды — здесь, сведения о пользовательских изменениях — в `CHANGELOG.md`. Документы должны попадать в коммит базы, от которой создаются новые рабочие копии.
3. Последовательные задачи можно выполнять в Local. Для одновременных изменений создавайте отдельный чат в режиме **Worktree**, задавая согласованную стартовую ветку. Каждый чат работает в своей папке и использует свои результаты сборки и тестов.
4. После реализации проверьте diff и тесты, затем оформите PR. Слияние и выпуск выполняются в рамках согласованной пользователем задачи. Изоляция worktree не устраняет возможные конфликты при последующем слиянии.

Шаблон первой задачи в новом чате:

> Прочитай AGENTS.md и DEVELOPMENT.md. Проверь рабочую папку, ветку и состояние Git. Задача: <описание>. Ожидаемый результат: <критерии>. Реализуй и проверь изменение. Публикация, слияние, выпуск и обновление установленной копии в эту задачу не входят.

Если публикация или обновление нужны, явно добавьте их к задаче. Не требуется пересказывать историю приложения: уточняйте только новое поведение и критерии результата.

## Среда и сборка

Нужна Windows с .NET Framework 4.8 и системным `csc.exe`. `Build.ps1` компилирует все `src/*.cs`; добавлять новый исходник в `.csproj` не требуется. Отдельный .NET SDK для основной программы не нужен. Используйте синтаксис, поддерживаемый текущим компилятором; не вводите новые зависимости без необходимости задачи.

Запускайте команды из корня своей рабочей копии:

```powershell
# Самостоятельное приложение, без PowerToys:
.\Build.ps1 -SkipPlugin

# Приложение и адаптер; укажите реальную папку PowerToys, если она отличается:
.\Build.ps1 -PowerToysPath (Join-Path $env:LOCALAPPDATA 'PowerToys')
```

Результат: `WheelPicker.exe` в корне; адаптер и его вспомогательные файлы — в `PowerToysRun/package`. Параметры `SkipPlugin` и отсутствие библиотек PowerToys означают, что адаптер не пересобран: не считайте старую папку `package` проверкой новой версии.

Адаптер версии 1.5.2 собирался против PowerToys 0.101 / .NET 10. При смене PowerToys проверьте совместимость его API. Основная программа при этом остаётся на .NET Framework 4.8.

## Изолированный запуск

Без `--data-dir` приложение использует `%LOCALAPPDATA%\WheelPicker\settings.json` и папку `Icons` рядом. Это реальные пользовательские данные. Для разработки выделяйте собственную папку:

```powershell
$previewData = Join-Path $PWD 'work\preview'
New-Item -ItemType Directory -Force -Path $previewData | Out-Null
Start-Process -FilePath (Join-Path $PWD 'WheelPicker.exe') -ArgumentList @('--settings', '--data-dir', ('"' + $previewData + '"'))
```

Такой запуск отключает изменение системного автозапуска, но всё ещё регистрирует глобальную горячую клавишу. Если установленная копия уже использует её, выберите свободное сочетание в изолированных настройках. Изоляция данных не изолирует глобальные клавиши Windows.

Основные аргументы: `--settings`, `--wheel`, `--background`, `--quit`, `--data-dir <папка>`. Команды адресуются экземпляру с тем же каталогом данных. При завершении тестового экземпляра всегда передавайте его `--data-dir`, чтобы не закрыть установленную копию.

## Проверки

```powershell
# Новая папка сохраняет результаты отдельно от других чатов:
$qaData = Join-Path $PWD ('work\qa-' + [guid]::NewGuid().ToString('N'))
.\Test.ps1 -TestDirectory $qaData
```

`Test.ps1` создаёт вспомогательные процессы и вызывает `--self-test` с отдельными данными. Основная квитанция — `test-results.txt`; снимки и дополнительные результаты находятся во вложенных папках. Тесты каталогов и окон зависят от Windows; их успешное прохождение не заменяет ручную проверку изменённого сценария. Сетевой загрузчик favicon в обычном наборе подменён.

Для изменения интерфейса проверьте оба языка, все три темы, обычный и минимальный размеры окна. Для изменения поведения проверьте соответствующие тесты и запустите обычный набор после сборки. В 1.5.2 было 5063 проверки приложения: это исторический результат, а не фиксированный ожидаемый счётчик.

Счётчик общего отчёта — число отдельных утверждений (`assertions`), а не независимых сценариев. Не умножайте проверки бизнес-логики на языки и темы, если они не влияют на поведение. В `RepeatLaunchTests` отдельно проверяются политика/мышь/клавиатура, геометрия подписей и снимки оформления. Геометрия сохраняет все размеры колеса 1–10 и позиции для двух языков и двух/трёх действий; палитры проверяются снимками без повторения той же логики. Для маршрутизации групп используются размеры 1, 6 и 10, разные стороны колеса и группы из 1–3 элементов. Квитанция `repeat-launch/results.txt` показывает раздельные результаты; количество снимков не добавляется к числу утверждений.

Отдельный тест настоящего клавиатурного ввода:

```powershell
.\Test.ps1 -NativeInput -TestDirectory (Join-Path $PWD ('work\input-' + [guid]::NewGuid().ToString('N')))
```

Он взаимодействует с фокусом и тестовым окном. Запускайте его только в согласованное время; не переключайте окна во время проверки. Не заявляйте о его прохождении по результатам обычного `Test.ps1`.

Отдельная проверка настоящего перетаскивания между процессами (также занимает мышь и фокус, запускается только в согласованный период):

```powershell
.\Test-DropInput.ps1 -TestDirectory (Join-Path $PWD ('work\drop-input-' + [guid]::NewGuid().ToString('N')))
```

Тестовый источник передаёт ссылку в браузерных форматах и локальный файл через Windows OLE. Проверяются сохранение фокуса источника, работа drop на масштабированном «+» после отпускания горячей клавиши, единственная форма, подтверждение/отмена и сохранность исходного файла. Это проверка внешнего источника и протокола Windows; конкретные версии браузеров отдельно не автоматизируются. Встроенный результат — `native-drop-results.txt`. В ограниченной песочнице синтетический ввод может не попасть в интерактивную сессию; такой запуск не считается успешным.

Для правок исключительно документации не нужна пересборка приложения: проверьте пути, параметры, ссылки, отсутствие персональных данных и `git diff --check`.

Проверка перетаскивания за всю строку: `Test-RowDragInput.ps1 -TestDirectory <новая папка>`. Она использует настоящую мышь и фокус тестового окна, поэтому запускается только в согласованный период, отдельно от обычных UI-проверок и других тестов ввода. Проверяются название, свободное место, значок и путь, создание группы с отменой, а также обычные клики по стрелкам, редактированию и удалению. Квитанция — `row-drag-results.txt`.

## Setup и проверка установщика

Нужен Inno Setup 6.7.3 или новее. Сначала соберите приложение **и адаптер**, затем:

```powershell
$innoCompiler = 'C:\Tools\Inno Setup 6\ISCC.exe' # замените на фактический путь
.\Build-Setup.ps1 -CompilerPath $innoCompiler -OutputDirectory (Join-Path $PWD 'dist')

.\Test-Setup.ps1 -CompilerPath $innoCompiler -TestDirectory (Join-Path $PWD ('work\setup-' + [guid]::NewGuid().ToString('N')))
```

Явный `-OutputDirectory` оставляет результаты внутри своего worktree. Без него `Build-Setup.ps1` пишет Setup в родительскую папку репозитория, что неудобно при нескольких рабочих копиях.

Результат — `Setup.exe` и `Setup.exe.sha256`. `Test-Setup.ps1` сам собирает тестовый установщик, проверяет установку в отдельную папку, обновление, сохранность данных, ярлыки и удаление. В 1.5.2 прошли 43 проверки установщика.

**Не запускайте тесты установщика параллельно.** Они используют общую запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\WheelPicker.Setup.Tests_is1`. Если осталась установка прошлого теста, сначала изучите его логи и штатно удалите именно этот стенд. Нехватка доступа к реестру в песочнице не означает дефект продукта; не ослабляйте проверки, чтобы скрыть ограничение среды.

Штатный установщик размещает приложение в `%LOCALAPPDATA%\Programs\WheelPicker`. У ранних установок EXE может находиться в `%LOCALAPPDATA%\Microsoft\PowerToys\PowerToys Run\Plugins\WheelPicker`. Определяйте реальный путь перед обновлением; не считайте внешние временные помощники из старого чата частью проекта.

## Выпуск версии

1. Соберите согласованные изменения в ветке, проверьте diff, конфиденциальные данные и результаты тестов. Перед отправкой убедитесь, что в коммит не попали `work`, `dist`, личные настройки и сборки.
2. При задаче на выпуск согласуйте номер и обновите `src/AssemblyInfo.cs`, `PowerToysRun/Main.cs`, `PowerToysRun/plugin.json`, значение по умолчанию в `Build-Setup.ps1` и `setup/WheelPicker.iss`. Обновите `CHANGELOG.md` и пользовательские README по существу изменений.
3. Соберите EXE, адаптер и Setup из одной версии; проведите проверки приложения и установщика. Перед релизом сверяйте версию и SHA-256 готового артефакта.
4. После согласованного слияния убедитесь, что тег `vX.Y.Z` указывает на нужный коммит `main`. Создайте релиз с кратким описанием и приложите Setup и SHA-256. Не заменяйте файлы предыдущих релизов. Ветки, коммиты и релизы — разные состояния публикации.
5. Обновление установленного приложения выполняйте, если оно входит в запрос. Сохраните приватную резервную копию настроек, остановите нужный экземпляр, обновите нужные файлы и проверьте версию, запуск и сохранность приложений, групп и предпочтений. Не переносите пользовательские данные в Git.
